Harness plan artifact

Plano de acao: Evolution Go + PostgreSQL self-host

Objetivo: migrar o WACRM de Meta Cloud API + Supabase para Evolution Go + PostgreSQL self-host, com fases pequenas, tasks rastreaveis, sub-tasks verificaveis, gates de aceite e handoff claro para agentes.

Tipo: migration Escopo: arquitetura + execucao futura Repo: wacrm Nao executar sem aprovacao
Fonte de verdade

Este arquivo define plano macro. Durante execucao, criar task Harness real apos adotar .harness/ no repo.

Ordem recomendada

Primeiro desacoplar providers e DB. Depois trocar conexoes. Corte direto aumenta risco de regressao em auth, inbox, flows e mídia.

Gate global

Nenhuma fase fecha sem evidencia: testes focados, smoke manual, rollback conhecido e impacto documentado.

Resumo executivo

A migracao tem dois eixos independentes, mas conectados: WhatsApp provider e infra de dados. Supabase hoje entrega banco, auth, RLS, storage, realtime e service role. PostgreSQL self-host cobre apenas banco; os outros recursos precisam substitutos explicitos. Evolution Go troca o modelo Meta/WABA/token/PIN por instancia/API key/QR/webhook/eventos.

Decisao critica: executar em fatias. Manter sistema rodando com provider antigo enquanto novos adapters e repositorios entram por tras de contratos internos.

Critérios de aceite globais

Funcionais

  • Admin configura Evolution Go sem campos Meta obrigatorios.
  • QR/pairing conecta instancia.
  • Inbound cria contato, conversa e mensagem.
  • Outbound manual salva e envia.
  • Automations e flows continuam operando.
  • Broadcast funciona com modelo local ou politica aprovada.
  • App roda sem variaveis Supabase obrigatorias apos corte.

Nao funcionais

  • Nenhum acesso cross-account em testes.
  • Secrets criptografados ou fora do client.
  • Backup/restore PostgreSQL testado.
  • Storage isolado por conta.
  • Webhook publico valida segredo.
  • Logs nao expõem API key, token, telefone completo quando evitavel.

Riscos principais

Risco Impacto Mitigacao
Auth/RLS mal substituido Vazamento entre contas Guards centrais, testes cross-account, revisao focada.
Endpoint Evolution divergente Envio/webhook falha Swagger real e fixtures antes do adapter.
Templates Meta sem paridade Broadcast muda comportamento Decisao explicita: desativar ou modelo local.
Realtime removido sem substituto Inbox parece travada Polling MVP; SSE/WebSocket posterior.
Migracao de storage incompleta Midia/avatar quebrados Inventario de buckets e runbook MinIO.
Cutover sem rollback Indisponibilidade prolongada Backup, restore e rollback testados em staging.
